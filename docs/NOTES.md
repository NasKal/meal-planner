## Τι έχουμε κάνει

**Υποδομή**
- Repo, deploy στο GitHub Pages με `npm run deploy` (gh-pages branch).
- Firebase: είσοδος email + κωδικός, Firestore με κανόνες ασφαλείας ανά νοικοκυριό.
- Κανόνες δοκιμασμένοι με 29 σενάρια και μια δοκιμή από άκρη σε άκρη σε πραγματικό browser.

**Λογαριασμός και νοικοκυριό**
- Εγγραφή, σύνδεση, ξέχασα τον κωδικό.
- Δημιουργία νοικοκυριού, πρόσκληση με κωδικό (μιας χρήσης, 7 ημέρες), είσοδος με κωδικό.
- Οθόνη λογαριασμού με μέλη, κωδικό πρόσκλησης, ημερομηνία έναρξης κύκλου, αποσύνδεση.

**Οθόνες**
- **Σήμερα:** πιάτο της ημέρας, υλικά, επόμενες 2 μέρες με υλικά, υπενθύμιση μουλιάσματος το προηγούμενο βράδυ. Σαββατοκύριακο δείχνει τη Δευτέρα.
- **Πλάνο:** 4 εβδομάδες × 5 μέρες, ισορροπία εβδομάδας, αλλαγή πιάτου (ίδια κατηγορία ή όλα, τυχαίο πιάτο, αγαπημένα πρώτα), προειδοποίηση για πάνω από ένα πιάτο με μανιτάρια. Live sync.
- **Βραδινά:** φορές ανά 2 εβδομάδες για βραδινά και πρωινό, με κουμπιά − και +.
- **Λίστα:** ανά κατάστημα και περίοδο, από πλάνο και βραδινά/πρωινά. Τικ live με όνομα, «Το έχω», έκτακτα προϊόντα, βασικά είδη, αντιγραφή λίστας.
- **Πιάτα:** αναζήτηση, φίλτρα, αγαπημένα, αξιολόγηση, επεξεργασία υλικών, νέο πιάτο, απόκρυψη, διαγραφή.

**Δεδομένα**
- 36 μεσημεριανά, 7 βραδινά, 2 πρωινά, 4 καταστήματα (Σκλαβενίτης, Λαϊκή, Ψαράς, Market Βάρδα) και το πλάνο 4 εβδομάδων, από το παλιό `legacy/index.html`.
- Ο κατάλογος μπαίνει στο νοικοκυριό την πρώτη φορά που θα ανοίξει κάποιος (`src/lib/seed.ts`).

## Τι μένει ανοιχτό

Με σειρά προτεραιότητας.

### 1. PWA και offline (επείγον πριν τα ψώνια της Παρασκευής 16/10)

- Manifest, εικονίδια, `apple-touch-icon`, ώστε να εγκαθίσταται στην αρχική οθόνη του iPhone.
- Service worker (`vite-plugin-pwa`), ώστε να ανοίγει χωρίς σήμα.
- Ένδειξη «Χωρίς σύνδεση · οι αλλαγές θα σταλούν».
- Δοκιμή: εγκατάσταση στο iPhone, αεροπλάνο mode, τικ στη λίστα, επαναφορά σύνδεσης και έλεγχος ότι συγχρονίστηκαν.
- Το Firestore έχει ήδη τοπική cache με ουρά αλλαγών (`src/firebase.ts`). Λείπει το κέλυφος της εφαρμογής.

### 2. Ημερομηνία κύκλου για την πραγματική χρήση

Τώρα η εβδομάδα 1 ξεκινά Δευτέρα 12/10. Αν η πραγματική χρήση ξεκινήσει Δευτέρα 19/10, η ημερομηνία αλλάζει από το εικονίδιο προφίλ, στο «Κύκλος 4 εβδομάδων». Τα τικ της λίστας μηδενίζονται μόνα τους με τη νέα ημερομηνία.

### 3. Μεταφορά δεδομένων από το παλιό app (αν χρειάζεται)

Το παλιό app κρατούσε δεδομένα στο `localStorage` (`mealplanner-v1`) ή σε κωδικό export base64. Το νέο ξεκίνησε με το αρχικό πλάνο. Να ρωτηθεί ο χρήστης αν είχε αλλαγές που θέλει να περάσουν (δικά του πιάτα, αλλαγές πλάνου).

### 4. Ρυθμίσεις νοικοκυριού

Σήμερα είναι σταθερές στον κώδικα:
- Ισορροπία εβδομάδας (1 όσπριο, 2 λαχανικά, 1 κρέας, 1 ψάρι) στο `WEEK_BALANCE` του `src/data/types.ts`.
- Όριο μανιταριών (1 ανά κύκλο).
- Αριθμός ατόμων: οι ποσότητες είναι πάντα για 2.
- Καταστήματα: δεν επεξεργάζονται (όνομα, χρώμα, ανά εβδομάδα ή ανά 2 εβδομάδες).
- Χύτρα ταχύτητας: δείχνει πάντα και τους δύο χρόνους.

### 5. Φάση 2 (από το brief)

- Συνταγές με βήματα, φωτογραφία, link.
- Τιμές και προϋπολογισμός.
- Έξυπνη πρόταση πλάνου με κανόνες.
- Μόνιμη αποθήκη «τι έχω στο σπίτι» (τώρα το «Το έχω» ισχύει μόνο για τη συγκεκριμένη λίστα).
- Δεύτερο νοικοκυριό (φίλοι): το μοντέλο το υποστηρίζει, δεν έχει δοκιμαστεί με δύο νοικοκυριά μαζί. Αντιγραφή πιάτων μεταξύ νοικοκυριών.

### 6. Τεχνικό χρέος και βελτιώσεις

- Αυτόματο deploy με GitHub Actions (χρειάζεται δικαίωμα `workflow` στο token του NasKal). Τώρα το deploy το τρέχει η εντολή `npm run deploy`.
- Οι κανόνες `firestore.rules` ανεβαίνουν χειροκίνητα με επικόλληση στην κονσόλα Firebase. Εναλλακτικά `firebase login` και `firebase deploy --only firestore:rules`.
- Το bundle είναι 265KB gzip (κυρίως Firebase). Μπορεί να σπάσει σε κομμάτια.
- Έλεγχος προσβασιμότητας με VoiceOver στο iPhone.
- Διαγραφή νοικοκυριού και «αποχώρηση από νοικοκυριό» δεν έχουν κουμπί στη διεπαφή. Οι κανόνες επιτρέπουν σε οποιοδήποτε μέλος να σβήσει το νοικοκυριό.
- Αλλαγή κωδικού μέσα από την εφαρμογή (τώρα μόνο «ξέχασα τον κωδικό»).
- Σύνδεση με Google για τους φίλους, αν ζητηθεί.

## Πώς δουλεύουμε

```
npm install
npm run dev                        # τοπικά
npm run build                      # έλεγχος TypeScript και build
npm run deploy                     # build και δημοσίευση στο GitHub Pages
APP_URL=https://naskal.github.io/meal-planner/ npm run test:e2e
```

- Η δοκιμή `tests/e2e-signup-join.mjs` φτιάχνει δύο προσωρινούς λογαριασμούς, περνά εγγραφή, πρόσκληση, πλάνο, λίστα, βραδινά, πιάτα, και σβήνει μόνη της ό,τι έφτιαξε. Χρειάζεται Chrome (`CHROME_PATH` αν δεν είναι στην προεπιλεγμένη θέση).
- Το `gh` CLI έχει περισσότερους από έναν λογαριασμούς: στο repo χρησιμοποιείται ρητά το token του NasKal (`GH_TOKEN=$(gh auth token --user NasKal)`), χωρίς αλλαγή του ενεργού λογαριασμού.
- Κεφαλαία ελληνικά πάντα χωρίς τόνους, μέσω `upperEl` στο `src/lib/text.ts`, ποτέ με CSS `text-transform`.
- Κείμενο όχι μικρότερο από 14px, στόχοι αφής από 48px, αντίθεση WCAG AA τουλάχιστον.

## Δομή

```
src/
  firebase.ts            σύνδεση Firebase και τοπική cache
  state/session.tsx      χρήστης, προφίλ, νοικοκυριό
  state/data.tsx         ζωντανά δεδομένα νοικοκυριού (πιάτα, πλάνο, τικ…)
  lib/                   κύκλος, πλάνο, λίστα αγορών, πιάτα, seed, σφάλματα
  data/                  τύποι και αρχικός κατάλογος (catalog.ts παράγεται από το legacy)
  screens/               Auth, Setup, Today, Plan, Evening, ShoppingList, Dishes, Settings
  ui/                    στοιχεία διεπαφής και CSS
  styles/                tokens (χρώματα, γραμματοσειρές), global
firestore.rules          κανόνες ασφαλείας (πηγή αλήθειας)
legacy/index.html        το αρχικό μονό αρχείο
tests/                   δοκιμή από άκρη σε άκρη
```
