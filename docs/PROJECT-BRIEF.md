# Meal Planner: Project Brief

Έκδοση 1.1 · 12/10/2026 · Fun project, χωρίς προθεσμία

Αλλαγές από την 1.0: το backend από Supabase γίνεται **Firebase** (Spark, δωρεάν) και η είσοδος από OTP γίνεται **email + κωδικός**.

## 1. Σκοπός

Να γίνει το `index.html` (σήμερα μονό αρχείο, δεδομένα μόνο στον browser κάθε συσκευής) πλήρης εφαρμογή που:

- τη χρησιμοποιούμε εγώ και η γυναίκα μου από δύο iPhone, με κοινό πλάνο και κοινή λίστα αγορών που ενημερώνονται live,
- φιλοξενείται στο GitHub Pages,
- μελλοντικά μπορεί να τη χρησιμοποιήσει και ένα ζευγάρι φίλων με δικό του, ανεξάρτητο πλάνο,
- έχει όσο το δυνατόν καλύτερο UX για τον πιο απλό καθημερινό χρήστη.

## 4. Λειτουργίες

### 4.1 Φάση 1: πρώτη έκδοση (εμείς οι δύο)

- Είσοδος με email και κωδικό, δημιουργία νοικοκυριού, πρόσκληση της γυναίκας μου με κωδικό.
- Πλάνο 4 εβδομάδων × 5 μεσημεριανά, με αλλαγή πιάτου, τυχαίο πιάτο, ενδείξεις ισορροπίας εβδομάδας. Live sync.
- Βραδινά και πρωινό (μετρητές ανά 2 εβδομάδες), με ποσότητες ανά άτομο (το πρωινό είναι μόνο για μένα).
- Λίστα αγορών ανά κατάστημα και περίοδο, με τικ που φαίνονται live στον άλλον.
- Ρυθμίσεις: καταστήματα, κανόνες, αριθμός ατόμων, πρώτη μέρα πλάνου, χύτρα ταχύτητας.
- Offline και PWA.
- Μεταφορά των υπαρχόντων δεδομένων (βλ. §8).

### 4.2 Φάση 2

- Πλήρης διαχείριση καταλόγου: επεξεργασία, απόκρυψη και διαγραφή όλων των πιάτων, αγαπημένα, αξιολόγηση.
- Αποθήκη "τι έχω στο σπίτι" που μένει μεταξύ περιόδων.
- Έκτακτα προϊόντα στη λίστα που δεν ανήκουν σε πιάτο.
- Τιμές και προϋπολογισμός.
- Συνταγές: βήματα, φωτογραφία, link.
- Δεύτερο νοικοκυριό (φίλοι), αντιγραφή πιάτων μεταξύ νοικοκυριών.
- Αυτόματη πρόταση ολόκληρου μήνα.

### 4.3 Δημιουργία πλάνου (πρόταση)

Το 🎲 μένει ως γρήγορο εργαλείο ανά μέρα. Προστίθεται κουμπί "Πρότεινε μου πλάνο" που γεμίζει τον κύκλο με κανόνες:

- τήρηση ισορροπίας εβδομάδας,
- χωρίς επαναλήψεις μέσα στον κύκλο,
- όρια ανά ετικέτα (π.χ. μανιτάρια ≤ 1),
- προτεραιότητα στα αγαπημένα και αποφυγή όσων έχουν χαμηλή αξιολόγηση,
- ο χρήστης βλέπει το αποτέλεσμα και το αλλάζει πριν "κλειδώσει".

### 4.4 Ένα "Σήμερα" χωρίς ημερολόγιο

Ο κύκλος μένει χωρίς ημερομηνίες, αλλά ο χρήστης ορίζει μία φορά "η εβδομάδα 1 ξεκινά τη Δευτέρα 12/10". Από εκεί η εφαρμογή ξέρει σε ποια εβδομάδα και ημέρα είμαστε και εμφανίζει αρχική οθόνη "Σήμερα / Αύριο". **Προς επιβεβαίωση.**

### 4.5 Εκτός πεδίου

Ημερολόγιο με ημερομηνίες και ιστορικό, push notifications, πολλαπλές γλώσσες, native εφαρμογή στο App Store, κύκλος διαφορετικού μήκους από 4 εβδομάδες.

## 5. UX και σχεδιασμός

Αρχές:

- **Μέγεθος:** κείμενο 17–18px ή μεγαλύτερο, τίποτα κάτω από 14px. (Σήμερα τα badges και τα βοηθητικά είναι ~11–12px.)
- **Αντίθεση:** WCAG AA τουλάχιστον (4.5:1 στο κείμενο), και AAA (7:1) στο κύριο κείμενο όπου γίνεται. Η κατάσταση δεν δηλώνεται μόνο με χρώμα (πάντα και εικονίδιο ή λέξη).
- **Αφή:** στόχοι ≥ 48px, χρήσιμα με ένα χέρι. Τα βασικά κουμπιά στο κάτω μισό της οθόνης.
- **Λειτουργία σούπερ μάρκετ:** μεγάλα τικ, τα τσεκαρισμένα πέφτουν στο τέλος, φαίνεται ποιος τα τσέκαρε, μικρή πρόοδος "12 από 31".
- **Λιγότερα βήματα:** το πιο συχνό (δες το σημερινό πιάτο, τικάρισμα) σε 1 πάτημα.
- **Ειλικρινείς καταστάσεις:** φαίνεται καθαρά όταν δεν υπάρχει σύνδεση, ότι οι αλλαγές θα σταλούν, και ότι έγινε sync.
- **Γραμματοσειρές:** με πλήρες ελληνικό subset, αυτοφιλοξενούμενες στο repo (offline, και χωρίς κλήση σε Google). Υποψήφιες: Literata, Alegreya Sans, Commissioner, IBM Plex Sans. Η τελική επιλογή γίνεται στη φάση σχεδίασης, με δοκιμή ότι ο τονισμός αποδίδεται σωστά.
- **Ταυτότητα:** κρατάμε το ζεστό χαρακτήρα (ελιά, άμμος, τερακότα) αλλά με νέα τυπογραφία, φόντο με βάθος και σχεδιασμένη κίνηση. Σκούρο θέμα ακολουθεί το iPhone.

Οθόνες (πλοήγηση κάτω, όπως τώρα): Σήμερα · Πλάνο · Βραδινά · Λίστα · Πιάτα, και Ρυθμίσεις.

## 6. Αρχιτεκτονική

```
iPhone (PWA) ──► GitHub Pages (στατικά αρχεία)
     │
     └──► Firebase: Authentication + Firestore (rules) + τοπική cache offline
```

Δεν χρησιμοποιούμε Cloud Functions ούτε Firebase Hosting. Έτσι μένουμε στο δωρεάν πακέτο Spark, χωρίς πιστωτική κάρτα.

### 6.1 Stack (πρόταση)

| Επίπεδο | Επιλογή | Γιατί |
|---|---|---|
| Build | Vite + TypeScript | Γρήγορο, απλό deploy σε Pages |
| UI | React | Μεγάλο οικοσύστημα, το project θα μεγαλώσει |
| Δεδομένα | Firebase JS SDK (Firestore, modular) | Live listeners, offline cache και ουρά αλλαγών ενσωματωμένα. Δεν χρειάζεται δεύτερη βιβλιοθήκη cache |
| PWA | `vite-plugin-pwa` | Service worker, εγκατάσταση, offline |
| CSS | CSS variables + CSS modules | Πλήρης έλεγχος του design, χωρίς έτοιμο "look" |
| Δοκιμές rules | Firebase Emulator Suite | Δοκιμή των κανόνων ασφαλείας τοπικά πριν το deploy |
| Deploy | GitHub Actions → Pages | Αυτόματο σε κάθε push στο `main` |

### 6.2 Φιλοξενία

- Δημόσιο repo στο GitHub Pages (το δωρεάν πακέτο δεν επιτρέπει ιδιωτικό repo για Pages). Ο κώδικας είναι ορατός, **τα δεδομένα όχι**.
- Το Firebase config (apiKey κ.λπ.) μπαίνει στο repo και είναι σχεδιαστικά δημόσιο. Η προστασία των δεδομένων γίνεται με τους κανόνες Firestore. Επιπλέον περιορίζουμε το API key στο domain `naskal.github.io` από την κονσόλα της Google Cloud.
- Το catalog των έτοιμων πιάτων είναι seed αρχείο στο repo.
- Οι κανόνες (`firestore.rules`) και τα ευρετήρια (`firestore.indexes.json`) ζουν στο repo και ανεβαίνουν με το Firebase CLI.

### 6.3 Είσοδος

- Authentication provider: **Email/Password**. Χωρίς επιβεβαίωση email, αφού η εφαρμογή είναι ιδιωτική.
- Ο κωδικός πληκτρολογείται μέσα στην εφαρμογή, άρα δεν υπάρχει το πρόβλημα με το iPhone (σύνδεση Safari έναντι PWA που έχουν οι σύνδεσμοι email). Το keychain του iPhone μπορεί να αποθηκεύει τον κωδικό.
- Ξέχασα τον κωδικό: το Firebase στέλνει μόνο του email επαναφοράς, δωρεάν και χωρίς δικό μας SMTP.
- Αν κάποιος τρίτος βρει το URL και φτιάξει λογαριασμό, **δεν βλέπει τίποτα**. Τα δεδομένα είναι προσβάσιμα μόνο σε μέλη νοικοκυριού (βλ. §7).
- Αργότερα, για τους φίλους, μπορεί να προστεθεί σύνδεση με Google χωρίς αλλαγή στα δεδομένα.

### 6.4 Live sync και offline

- Κάθε οθόνη ακούει (`onSnapshot`) τις συλλογές που χρειάζεται και ενημερώνεται live.
- Το Firestore γράφει πρώτα τοπικά (άμεση ανταπόκριση), κρατά ουρά αλλαγών και τις στέλνει μόλις υπάρχει σύνδεση. Ενεργοποιούμε persistent cache.
- Σε σύγκρουση ισχύει η πιο πρόσφατη αλλαγή ανά έγγραφο (last-write-wins). Για τικ είναι αρκετό. Οι μετρητές (βραδινά) χρησιμοποιούν `increment()`, ώστε δύο ταυτόχρονα πατήματα από δύο κινητά να μετρηθούν και τα δύο.
- Εγκατεστημένο PWA σε iOS κρατά τα τοπικά δεδομένα του, αλλά το Safari μπορεί να τα σβήσει μετά από 7 ημέρες χωρίς χρήση εκτός PWA. Γι' αυτό η αλήθεια μένει πάντα στον server.
- Όρια Spark (ενδεικτικά): 1 GiB αποθήκευση, 50.000 αναγνώσεις και 20.000 εγγραφές ημερησίως. Για δύο ή τέσσερα άτομα είναι πολύ πάνω από όσα χρειάζονται.

## 7. Μοντέλο δεδομένων (Firestore)

Όλα τα δεδομένα ζουν κάτω από `households/{householdId}`, ώστε οι φίλοι να προστεθούν χωρίς αλλαγή δομής.

| Διαδρομή | Πεδία | Σχόλια |
|---|---|---|
| `users/{uid}` | displayName, householdId | Προφίλ και σε ποιο νοικοκυριό ανήκει |
| `households/{hid}` | name, memberIds[], cycleStartDate, settings{}, schemaVersion | Settings: άτομα, χύτρα, πρώτη μέρα, κανόνες |
| `households/{hid}/stores/{id}` | name, color, cadence (εβδομαδιαίο / ανά 2 εβδ.), sort | Seed: Σκλαβενίτης / My Market, Λαϊκή, Ψαράς, Market Βάρδα |
| `households/{hid}/dishes/{id}` | kind (μεσημεριανό / βραδινό / πρωινό), name, category, minutes, minutesPressure, tags[], note, favorite, rating, hidden, people, ingredients[], sourceDishId | Τα έτοιμα πιάτα αντιγράφονται στο νοικοκυριό όταν δημιουργείται, ώστε να επεξεργάζονται ελεύθερα |
| `households/{hid}/plan/{week-slot}` | dishId, updatedBy, updatedAt | 20 έγγραφα, ένα ανά θέση |
| `households/{hid}/extras/{dishId_period}` | count, updatedBy, updatedAt | Βραδινά και πρωινό, με `increment()` |
| `households/{hid}/checks/{store_period_itemKey}` | checked, checkedBy, checkedAt | Τα τικ της λίστας |
| `households/{hid}/pantry/{itemKey}` | have, qty, updatedBy, updatedAt | Το "το έχω" |
| `households/{hid}/manualItems/{id}` | storeId, period, name, qty, unit, done | Έκτακτα προϊόντα |
| `households/{hid}/prices/{itemKey_store}` | price, updatedAt | Φάση 2 |
| `invites/{code}` | householdId, expiresAt, createdBy | Κωδικός πρόσκλησης |

Κάθε ingredient μέσα στο `ingredients[]`: `{name, qty, unit, storeId, section}`.

Το `itemKey` είναι το κανονικοποιημένο όνομα συν μονάδα, χωρίς το χαρακτήρα `/` (δεν επιτρέπεται σε id εγγράφου).

Κανόνες νοικοκυριού (στα settings): ισορροπία εβδομάδας `{legume:1, veg:2, meat:1, fish:1}`, όρια ανά ετικέτα `{mush: 1}`, λίστα εξαιρέσεων (ρύζι, λάχανο, νιόκι, τσιπούρα, λαβράκι), αριθμός ατόμων.

Η λίστα αγορών **δεν αποθηκεύεται**: υπολογίζεται στον client από πλάνο, βραδινά και πιάτα. Αποθηκεύονται μόνο τα τικ και το "το έχω".

### Κανόνες ασφαλείας (Firestore Security Rules)

- Ο χρήστης διαβάζει και γράφει μόνο σε νοικοκυριά όπου το uid του υπάρχει στο `memberIds`.
- Η δημιουργία νοικοκυριού επιτρέπεται σε κάθε συνδεδεμένο χρήστη, με τον ίδιο ως μοναδικό μέλος.
- Η εγγραφή σε νοικοκυριό γίνεται μόνο με έγκυρο, μη ληγμένο κωδικό πρόσκλησης. Επειδή δεν έχουμε Cloud Functions, ο έλεγχος γίνεται μέσα στους κανόνες. Ο ακριβής μηχανισμός σχεδιάζεται και δοκιμάζεται με το emulator στο Βήμα 2.
- Οι κωδικοί πρόσκλησης είναι μακροί και τυχαίοι (όχι λίστα, μόνο ανάγνωση με γνωστό κωδικό).
- Δεν υπάρχουν migrations σχήματος: το `schemaVersion` του νοικοκυριού επιτρέπει να γράψουμε μελλοντική μετατροπή δεδομένων όταν χρειαστεί.

## 8. Μεταφορά υπαρχόντων δεδομένων

Υπάρχουν δύο πηγές:

1. `localStorage` (`mealplanner-v1`) στη συσκευή που τρέχει ήδη το app.
2. Ο κωδικός export (base64) που παράγει το τωρινό app.

Στην πρώτη είσοδο η εφαρμογή προσφέρει "Εισαγωγή από το παλιό app": διαβάζει το `localStorage` ή δέχεται τον κωδικό, και μεταφέρει πλάνο, μετρητές, δικά μας πιάτα και "το έχω" στο νέο νοικοκυριό.

## 9. Βήματα υλοποίησης

0. **Στήσιμο:** repo στο GitHub (Naskal), project στο Firebase (Authentication, Firestore), κενό app με deploy στο Pages, επιβεβαίωση stack.
1. **Σύστημα σχεδίασης:** γραμματοσειρές, χρώματα, στοιχεία (κάρτες, κουμπιά, τικ), σκούρο θέμα. Δοκιμή στο iPhone.
2. **Είσοδος και νοικοκυριό:** email + κωδικός, δημιουργία, πρόσκληση, κανόνες ασφαλείας.
3. **Δεδομένα και πλάνο:** seed του καταλόγου, οθόνες Σήμερα/Πλάνο, live sync.
4. **Λίστα αγορών:** παραγωγή λίστας, τικ live, ρυθμίσεις καταστημάτων και κανόνων.
5. **Offline και PWA:** persistent cache, εγκατάσταση, έλεγχος χωρίς σήμα.
6. **Μεταφορά δεδομένων και δοκιμή από εμάς τους δύο** πριν περάσουμε στη Φάση 2.

## 11. Γνωστά προβλήματα του τωρινού κώδικα που λύνονται στη μετάβαση

- Το "το έχω" και τα τικ είναι ανά συσκευή και το "το έχω" ισχύει καθολικά ανά όνομα, ανεξάρτητα από την περίοδο.
- Ονόματα καταστημάτων, κανόνες και κατηγορίες είναι σκληροκωδικοποιημένα.
- Οι ποσότητες είναι πάντα για 2 άτομα.
- Η συγχώνευση υλικών γίνεται με όνομα και μονάδα, χωρίς μετατροπές (γρ/κιλό, κουτί).
- Οι γραμματοσειρές είναι μικρές και χωρίς σχεδιασμένη τυπογραφία.
